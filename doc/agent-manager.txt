1. Introduction                                      *agent-manager-intro*

Agent Manager presents Codex and Claude agents in native Neovim buffers. Its
embedded Rust broker owns one live agent. Durable mode connects to a supervised,
owner-only Unix socket and keeps multiple agents alive across SSH and Neovim
restarts. M2 added safe interaction, M3 added the immutable `agent.manager` UX
contracts, and M4 added replay/resync, metadata persistence, and writer
isolation.

==============================================================================
2. Setup                                              *agent-manager-setup*

>lua
    require("agent_manager").setup({
      broker = {
        command = { "/path/to/agent-manager-broker", "serve" },
      },
      providers = {
        claude = {
          python = "/path/to/worker-venv/bin/python",
        },
      },
      ui = {
        external_sessions = true,
        external_session_limit = 1000,
      },
    })
<

A source checkout discovers target/release or target/debug broker artifacts
and python/.venv/bin/python relative to the plugin root when present. Startup
never builds or installs dependencies.

Durable mode requires an already supervised broker plus absolute executable
and socket paths:

>lua
    require("agent_manager").setup({
      broker = {
        mode = "durable",
        command = { "/home/ai/.local/bin/agent-manager-broker", "serve-durable" },
        socket = "/run/user/1000/agent-manager/broker.sock",
      },
    })
<

The durable client reconnects with capped backoff. Closing or tearing down the
view disconnects Neovim only; it never shuts down the supervised broker.

                                                   *:AgentManagerSteer*

4. Workspace                                      *agent-manager-workspace*

The native workspace uses agents, conversation, and activity buffers. Wide
displays show all three. Medium and narrow displays use <Tab> and <S-Tab> to
cycle panes.

The Agents pane is a working-directory tree containing broker-owned agents and
active sessions started by the standalone Codex or Claude CLI. External rows
are labeled "cli-running" and remain read-only while the originating terminal
owns them. The tree is refreshed when the workspace opens and with `r`.
Set `ui.external_sessions` to false to hide external CLI sessions;
`ui.external_session_limit` caps each provider query from 1 to 1000.

    n       start an agent
    h       attach to or resume a session
    p       prompt the selected agent
    s       steer an active turn
    x       confirm an interrupt
    a / d   allow or deny only the focused human request
    <CR>    answer a focused question or select an agent
    c       queue explicit editor context
    f       fork the selected provider session
    A       archive the selected inactive agent
    D       show a workspace diff or dirty-buffer conflict
    r       refresh agents and external CLI sessions
    ?       show mapping help
    q       close the workspace view

Mappings are buffer-local. Closing the view does not approve, interrupt, or
delete provider state. A provider approval or question opens a dedicated
decision buffer that normal streaming redraws do not replace.

5. Safety                                            *agent-manager-safety*

Live prompts may consume provider quota. Credentials stay in the installed
provider runtimes and never enter Agent Manager configuration. Human callbacks
fail closed on timeout, cancellation, disconnect, malformed response, or
shutdown. The UI exposes only decisions advertised for the pending request.

Editor context is explicit and one-shot. Unsaved snapshots are marked but never
written automatically. An external change never reloads a modified buffer; use
|:AgentManagerDiff| to inspect, compare, explicitly reload, or keep it.

Embedded state ends when its broker exits and supports one live runtime. The
durable broker persists provider identity and transcript-free metadata, replays
retained events, and reloads provider history when replay is too old. Shared
Git checkouts permit one writable agent across all subdirectories. Additional
writable agents require distinct, existing linked worktrees; Agent Manager
validates but never creates or removes them. A fork keeps its source as a
disconnected summary so writer ownership remains explicit.

External CLI discovery projects metadata only. Prompt previews and tool
payloads do not cross into the Neovim model. Agent Manager does not attach to,
resume, interrupt, or otherwise seize a session while its standalone CLI owns
the provider writer.

6. UX integration                                       *agent-manager-ux*

Native presentation has no UX dependency. When UX Foundation schema v1 is on
the runtimepath, Agent Manager registers the immutable `agent.manager` manifest
and Foundation owns the AgentManager* groups and profile replay. UX Styling
discovers `ux_styling_adapter.agent_manager` without loading the Agent Manager
runtime, starting the broker, or reading domain data.

Agent Manager does not write tabline, statusline, winbar, statuscolumn, fold,
or scrollbar expressions owned by UX Chrome. Cached consumers may call:

>lua
    require("agent_manager").status()
    require("agent_manager").running_count()
    require("agent_manager").pending_approval_count()
<

These reads do not initialize the runtime. A scheduled
`User AgentManagerStateChanged` event carries running_count,
pending_approval_count, agent_ids, and a non-sensitive reason. It never carries
prompt text, messages, tool payloads, or credentials. The current Chrome
contract has no public segment API, so Agent Manager does not use Chrome
internals. UX Panels is not available at the M3 compatibility pins; the view
backend remains native and |:AgentManagerHealth| reports that choice.
